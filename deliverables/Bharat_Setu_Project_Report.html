Submission for: Hackathon — theme AI for Bharat & Public Services Live application: https://webapp-kohl-six-95.vercel.app Source code: https://github.com/no6546559-sketch/bharat-setu Team size: solo–4 (project is designed for a small team; all roles merged in this build) Report date: 11 October 2026

1. Executive Summary

India operates one of the largest social-welfare systems on earth. Yet a large share of eligible citizens never receive the benefits they are legally entitled to. The binding constraint is almost never money — it is information asymmetry: schemes are scattered across dozens of central and state portals, most interfaces are English-first, the forms are not explained, and a layer of middlemen profits from that confusion.

Bharat Setu ("India Bridge") is a multilingual, explainable, offline-first AI assistant that closes that gap. A citizen enters a short profile once and receives:

  • every government scheme they are eligible for, with the exact reason they qualify;
  • a document-readiness score telling them precisely what is missing and where to get it;
  • a formal RTI / grievance / certificate letter they can print and submit the same day;
  • an estimated annual benefit value in rupees, tracked application-by-application;
  • a What-if simulator that turns eligibility into a live dial — move age and income and watch

what opens up or closes, without touching the saved profile;

  • a Household plan that combines several family members into one benefit total;
  • a fraud shield that reads a suspicious SMS and explains, in plain language, exactly

what is happening and what to do next.

It does all of this in 13 Indian languages (including RTL Urdu), by voice or text, and with no internet connection required — because the entire reasoning engine runs on the device.

3.1 Core innovation — explainable eligibility

Most "scheme finders" return a bare list. Bharat Setu returns a verdict with evidence. For every scheme the engine emits structured reasons and blockers, e.g.:

✓ Age 34 is within the eligible band 18–120 ✓ Rural residence matches the scheme area ✓ Land holding 1.5 acre(s) is within limits ✕ Income limit is ₹6,00,000/year

This is produced by a rule engine over a machine-readable rules{} block stored with each scheme — not by an LLM. That means it is deterministic, auditable, instantaneous, and works offline.

3.2 Core innovation — grounded AI with graceful degradation

The optional LLM layer is never the source of truth. The serverless function builds its system prompt directly from the same curated knowledge base the UI uses and is instructed to cite only official .gov.in / .nic.in portals. If no key is configured, the upstream is down, or the response looks ungrounded, the handler returns {ok:false, fallback:true} and the client seamlessly answers from the deterministic offline engine. The user therefore never sees a fabricated scheme, amount or URL — the failure mode is less rich, never wrong.

3.3 Core innovation — offline-first

All eligibility, document, letter and fraud logic ships as static JavaScript and is cached by a service worker. A citizen in a low-connectivity district retains full functionality. This is the single most important design decision for the "Bharat" context.

3.4 Designed for the actual user

  • 13 languages — English, Hindi, Bengali, Tamil, Telugu, Marathi, Gujarati, Kannada,

Malayalam, Punjabi, Odia, Assamese, Urdu (with full RTL layout).

  • Voice in & out via the Web Speech API, locale-matched per language.
  • Font scaling to 140 %, high-contrast mode, dark mode.
  • Simple Mode — one tap enlarges text, calms the layout and hides decorative elements for

first-time internet users.

4.1 Deliberate architectural choice — zero build step

The application is a plain static bundle plus one serverless function. There is no bundler, no front-end framework and no runtime filesystem access. Consequences:

  1. The same api/ai.js handler runs under the local dev server and on Vercel, so local

and production behaviour are identical.

  1. A static bundle is trivially cacheable, and caching is what makes offline mode viable.
  2. Tiny footprint → fast on 3G and on low-end devices, which is the target.

6. Feature Detail and Walkthrough

6.1 Scheme Finder — explainable matching

The engine evaluates hard identity conditions (women-only, widow, disability, TB, girl-child, farmer, employed …) as blockers, then scores soft/quantitative conditions (age band, income ceiling, land holding, rural/urban, category interest). Verdicts: high / mid / low / none. Every surviving match carries human-readable reasons; every blocked scheme shows why.

6.2 What-if simulator — eligibility as a dial, not a verdict (new)

Eligibility feels fixed and final to a citizen, but it is really a function of a few numbers. The simulator puts age and annual income on live sliders and re-runs the full rule engine on every move — without touching the saved profile. As the sliders move, the citizen watches three things change in real time:

  • the number of matched schemes and the count of strong matches;
  • the estimated annual benefit value;
  • a diff against their current result: "Newly eligible" and "Would no longer qualify".

This turns a static list into a planning tool. A parent can see exactly how far over an income ceiling they are; a young person can see what opens up at a given age. It runs entirely offline.

6.3 Household mode — one plan for the whole family (new)

Welfare in India is claimed by households, not by individuals. Household mode lets the user save several family members, each with their own full profile, then:

  • switch between members with one tap (loading a member re-runs their eligibility instantly);
  • view a household summary table — each member's match count, strong-match count, top three

schemes and estimated annual value — with a combined household total;

  • export the whole household plan as a single text file to carry to a CSC or Panchayat office.

Member profiles are stored only in the browser's localStorage. Nothing is uploaded.

6.4 My Plan — from discovery to disbursement (new)

Discovery is only the first mile. My Plan turns a match list into an actionable plan:

  • Application tracker — mark each scheme *Not started → Applied → Benefit received →

Rejected (escalate)*, with an optional reference-number note.

  • Document-readiness bar per scheme, driven by the Document Checker state.
  • Estimated annual benefit value in ₹, computed conservatively by parsing each matched

scheme's headline amount (monthly amounts annualised). Presented as an itemised table with a total — a tangible, motivating number.

  • Export the whole plan as a .txt, share it via the Web Share API, or print it to

PDF to carry to a CSC, bank or Gram Panchayat office.

6.5 AI Assistant — grounded, multilingual

Text or voice in any of 13 languages. The classifier detects intent (eligibility, documents, how-to, status, amount, grievance, RTI, fraud, health, education, employment, pension, agriculture, housing, women, water, help), extracts entities (age, income, land) and selects evidence schemes. The LLM layer refines the answer; the offline engine guarantees one always exists.

6.6 Document Checker

Tick what you already have → a readiness percentage, the exact missing documents, and for each one the issuing office and expected timeline (e.g. Income certificate — apply on the state e-District portal or CSC; the Tehsildar/Revenue office issues it; 7–15 days).

6.7 RTI & Letters

Four legally-shaped templates — RTI application (cites Section 6(1), the ₹10 fee, the 30-day statutory deadline and the appellate authority), public grievance, scheme representation, and certificate request. Each is refined by the AI when available and always available offline. Print, copy or download.

6.8 Fraud Shield

A transparent, weighted rule set scores a pasted SMS/WhatsApp message out of 100: OTP/PIN requests, artificial urgency, shortened/throwaway domains, up-front "processing fees", lottery claims, APK/screen-share pushes, bank-detail harvesting, brand impersonation, job scams, fake free-scheme offers, and generic mass-mailing language. Genuine .gov.in/.nic.in domains register as a positive signal (with a negative lookahead so a phishing lookalike such as pmkisan.gov.in.xyz cannot masquerade as safe). Output: verdict, the red flags explained, and concrete next steps (call 1930 within the golden hour, report on cybercrime.gov.in, block the card, report to Sanchar Saathi).

6.9 Accessibility and inclusion

Skip link, ARIA live regions, keyboard-operable controls, semantic landmarks, 13 languages with correct dir="rtl" for Urdu, font scaling to 140 %, high-contrast and dark themes, optional spoken output for every answer, and a dedicated Simple Mode for first-time users.

7.3 Automated verification

node scripts/verify.mjs executes 63 assertions against the shipped bytes (not a re-implementation), covering:

  • Eligibility engine — ranking, farmer/BPL/women paths, hard exclusions, age boundaries,

and income ceilings (including the corrected ESIC ₹3,00,000 limit case).

  • Document intelligence — catalogue build, readiness scoring, per-document guides.
  • Fraud shield — scam detection, official-domain positive signal.
  • Multilingual NLU — intent classification and entity extraction (age/income/land).
  • Grounded offline answers — citations, RTI routing, fraud routing.
  • Letter generator — all four letter types.
  • i18n completeness — all 13 languages.
  • Live /api/ai endpoint — status and graceful fallback.

Result: 63 passed, 0 failed. The build validator additionally confirms every scheme carries an official portal link, all scheme IDs are unique, and both serverless modules are present.

7.4 Graceful degradation verified in production

On the live deployment the API currently reports ai_enabled:false (no LLM key configured in the Vercel project) and POST /api/ai returns {ok:false, fallback:true}. The client transparently serves the deterministic offline engine — every feature remains fully functional. This is the intended failure mode and is validated by the test suite.

9. Limitations and Responsible Use

  • Benefit amounts and eligibility criteria are indicative and change by government

notification. Every scheme card links the official portal and the app instructs the user to confirm before applying.

  • This is not a government website. It does not accept applications, hold funds, or

represent any department.

  • Privacy: all profile data, tracker state and chat history live only in the browser's

localStorage. Nothing is uploaded. Only free-text the user explicitly submits (question, letter details, suspicious message) is forwarded to the LLM — and only while online.

  • The app never requests, and should never be given, OTPs, PINs, CVVs or full bank/Aadhaar

numbers.

11. Conclusion

Bharat Setu demonstrates that the hardest problem in Indian welfare delivery is not eligibility — it is access. By combining an explainable, offline, multilingual reasoning engine with a grounded AI layer that can only ever add richness, never risk correctness, the project delivers a tool that a first-time internet user in a low-connectivity district can genuinely use to find, claim and track the benefits they are owed.

It is live, open-source, fully tested, and built to run where it is needed most — at the edge, on a phone, in the citizen's own language.
